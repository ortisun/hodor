# auth-ui

## Overview

The hosted pages of Hodor (package `hodor-auth-ui`, "registration, sign-in
and password recovery" in `package.json`): a React and Vite single-page
application built on Astryx with the Hodor theme. The server serves
`dist/index.html` for every page and `dist/assets` under `/auth-ui/assets`
(comment in `vite.config.ts`, which points to
`docs/architecture/hosted-pages.md`). The pages live at `/t/{tenant}/account`
and talk only to the interaction interface under `/t/{tenant}/interaction`.
This directory holds the build, lint, type and browser test configuration.
The application is in [src](./src/EGM.md), and the end-to-end tests are in
[browser-tests](./browser-tests/EGM.md). The theme in `src/themes/hodor` is
also used by `frontend/admin-console` and `frontend/design-system/showcase`.

## Interface

- `package.json:scripts` - `build` (`tsc --noEmit && vite build`),
  `typecheck` (`tsc --noEmit`), `theme` (`astryx theme build
  src/themes/hodor/hodorTheme.ts`), `theme-check` (the same with `--check`),
  `lint` (`eslint .`), `test` (`vitest run`), `browser-tests` (`playwright
  test`). There is no `dev` script.
- `vite.config.ts` - `base` `/auth-ui/`; builds to `dist` with
  `emptyOutDir`, `assetsInlineLimit: 0`, `modulePreload: { polyfill: false }`
  and no source maps. `test` is Vitest with `jsdom`, files
  `src/**/*.test.{ts,tsx}`, and `restoreMocks`.
- `playwright.config.ts` - `testDir: "browser-tests"`, `globalSetup:
  "./browser-tests/stack.ts"`, one worker, Chromium only, `baseURL` from
  `HODOR_URL` (default `http://localhost:8080`), locale `en-US`.
- `index.html` - `<html lang="en" data-theme="light">`, `robots: noindex`,
  the `#root` mount, `/src/main.tsx`, the icon `/src/door.svg`, and a
  `noscript` line in English and Portuguese.
- `tsconfig.json` - strict TypeScript (`noUncheckedIndexedAccess`,
  `verbatimModuleSyntax`, `noEmit`) over `src`, `browser-tests` and the
  configuration files.
- `eslint.config.js` - `typescript-eslint` strict, React hooks rules; ignores
  `dist`, `node_modules`, `test-results`, `playwright-report`,
  `src/astryx-themes.ts` and `src/themes/hodor/hodor.*`.
- Subdirectories:
  - [src](./src/EGM.md) - entry `main.tsx`, `App`, the address helpers
    (`address.ts`), the interaction client (`client.ts`), and the
    [messages](./src/messages/EGM.md), [pages](./src/pages/EGM.md),
    [parts](./src/parts/EGM.md) and [themes](./src/themes/EGM.md) folders.
  - [browser-tests](./browser-tests/EGM.md) - Playwright scenarios for
    registration, sign-in, recovery, the profile page, identity providers, directories, SAML,
    keyboard use, accessibility and the Content Security Policy.

## Invariants

- Content Security Policy: the built pages need no inline script, style or
  data address. `vite.config.ts` sets `assetsInlineLimit: 0` and turns off
  the module-preload polyfill (its comments give the reason), and
  `eslint.config.js` makes the JSX attributes `dangerouslySetInnerHTML` and
  `style` lint errors. The theme is compiled ahead of time for the same
  reason (`src/themes/hodor/hodorTheme.ts`).
- The assets are built for the base `/auth-ui/`, where the server serves
  them.
- `src/astryx-themes.ts` and `src/themes/hodor/hodor.*` are generated by `npm
  run theme`; `npm run theme-check` verifies them and lint skips them.
- `npm run browser-tests` needs the development stack running first (see
  [browser-tests](./browser-tests/EGM.md)).

## Side Effects

- `npm run build` empties and writes `dist`.
- `npm run theme` rewrites `src/astryx-themes.ts` and the generated files in
  `src/themes/hodor`.
- `npm run browser-tests` acts on the running stack (registrations, sign-ins
  and mail on the tenant under test) and writes `playwright-report` and
  `test-results`.

## Verification

- Run from `frontend/auth-ui`: `npm test`, `npm run typecheck`, `npm run
  lint`, `npm run theme-check`.
- With the development stack running: `npm run browser-tests`.
