# frontend

## Overview

The browser code of Hodor: three separate npm packages built with React, Vite and TypeScript on the Astryx component library. There is no shared workspace manifest at this level; each package has its own `package.json` and lock file. The hosted pages and the administration console are built into the container image by the `pages` stage of `deploy/docker/Dockerfile` (`npm ci` and `npm run build` in `frontend/auth-ui` and `frontend/admin-console`). The showcase is never shipped.

The Hodor theme has one home, `frontend/auth-ui/src/themes/hodor`. The other two packages reach it only through the `@hodor-theme` alias in their `vite.config.ts`.

## Subdirectories & Boundaries

- auth-ui: [./auth-ui/EGM.md](./auth-ui/EGM.md) - Package `hodor-auth-ui`, the hosted pages (sign-in, registration, password recovery, account, the return from an identity provider). Served under base `/auth-ui/` and shown at `/t/{tenant}/account`. `src/client.ts` is the only code that knows the interaction interface under `/t/{tenant}/interaction`. Holds the Hodor theme (`src/themes/hodor`, generated by `npm run theme`) and the Playwright browser tests (`browser-tests`), which need the development stack running.
- admin-console: [./admin-console/EGM.md](./admin-console/EGM.md) - Package `hodor-admin-console`, the administration console under `/t/{tenant}/console`: users and their sessions, identity providers, the audit log. `src/client.ts` is the only module that knows the console interface under `/t/{tenant}/console/api`. Buttons that change something render only when `may(me.permissions, action)` allows it, and dangerous actions go through the `Confirm` dialog.
- design-system: [./design-system/EGM.md](./design-system/EGM.md) - Holds `showcase` (package `hodor-design-system-showcase`), a static application with sample data that renders Astryx components under the Hodor theme. It makes no network or storage calls.

## Invariants

- The shipped pages (`auth-ui` and `admin-console`) need no inline script, style or data address, because of the Content Security Policy: their `vite.config.ts` files set `assetsInlineLimit: 0`, and their ESLint configurations forbid the JSX attributes `style` and `dangerouslySetInnerHTML`.
- Requests from `auth-ui` and `admin-console` are same-origin, with `cache: no-store` and `redirect: error`, and carry the `X-CSRF-Token` header on every request that is not a GET once the server has handed out a token (`client.ts` in each package).
- The tenant comes only from the browser address (`placeOf` in each package's `src/address.ts`).

## Verification

- Run from `frontend/auth-ui`: `npm run theme-check`, `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, and `npm run browser-tests` with the stack from `deploy/docker/compose.yaml` running.
- Run from `frontend/admin-console`: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`.
- Run from `frontend/design-system/showcase`: `npm run build` (it has no test script).
- These are the steps of the `pages`, `console` and `showcase` jobs in `.github/workflows/ci.yml`. Install first with `npm ci`.
